The loop

Build, break, repeat until nothing breaks.

0x01

Every ticket goes round the same track. Verifiers who never saw the code attack the running system from the spec alone. Anything they find sends the ticket back to prepare for another round. A clean verdict is the only exit forward.

round1
stageinput
verdict—
Round one finds the gap the brief never mentioned. Round two is clean. The token only moves forward on a clean verdict.
Stage by stage

Eight stages, each with one job.

0x08
01
prepare

Maps the repository, writes the context file, sizes the work and splits it when it is too big for one spec. A cartographer and a decomposer do the reading so later roles start warm.

02
spec-task

Writes a verifier-safe spec, has an independent intent verifier and a critic check it, then builds, tests, security- and UX-reviews, mutation-audits and burns the change in. The builder never grades its own work.

03
adversarial-review

Three personas attack the running system from the spec alone: a fuzzer, an attacker and a stranger who has never seen the ticket. Findings carry a fingerprint so a repeat is recognised.

04
pr

Pushes the branch and writes the PR body from the run's own files: intake becomes Problem, the build summary becomes Solution, QA and mutation reports become Testing. Draft by default.

05
nurses

The heartbeat keeps the PR alive. A build nurse reads CI and retries known flakes, a review nurse classifies comments and answers or fixes, and a sanity check once confirms the diff matches the description.

06
merge

Behind a gate. The dashboard shows the one line to type to pass it, or you set unattended merge once in the config and never see the gate again.

07
deploy-sentinel

Watches a window after the deploy: error counts, the metrics the ticket named, open incidents. A regression writes a finding and the loop reopens instead of a human noticing on Monday.

08
learner

Writes a lesson from the run and tunes a few marked config keys. When a lesson repeats it opens a draft PR against the engine's own reference files, citing the lesson.

The valve

A loop that cannot stop is a bill. This one escalates.

The loop ends on its own only when the verifiers pass everything. Everything else trips the valve and hands you one question.

5
rounds

The default budget. Round six never starts; the run writes an escalation instead.

×2
same finding

A fingerprint that survives a fix attempt in two consecutive rounds means the spec is wrong, not the code.

$
budget

Tokens, minutes and inner passes each have a ceiling in the config. Blow one and the governor trips.

?
one question

The escalation file ends with the single question that unblocks the run. Answer it, type go, and round N+1 reads your answer.

The front door

Everything starts with one command.

0x04
01 / INTAKE

Anything in

A sentence, a tracker key, a chat permalink, a doc link, a PR, a CI build, or several on one line. The classifier prints a three-line reading before any write: what it saw, the intent it chose, the next action. If that is wrong, say so. Nothing has happened yet.

classifyreadingrefine
02 / DISCOVERY

Profiles, not vendors

The engine asks for capabilities. On first run it looks at the MCP tools in the session, the CLIs on PATH and the repository's own signals, writes a profile that maps each capability to what this machine has, and asks one question about the gaps that change behaviour.

profile.mdconfig.jsonrediscover
03 / HEARTBEAT

Tick every fifteen minutes

One heartbeat runs whatever is due for every active run: nurse passes, sentinel windows, factory shifts that fill dispatch slots with the next ready tickets. Epics are planned into a graph and their ready set is dispatched in parallel.

tickfactoryepic-intake
04 / DEGRADATION

Missing tools, named

No tracker? A file tracker under the factory home. No observability? The sentinel is skipped and the dashboard says so. No PR capability? The run stops before the PR stage with a message naming what it needs. Nothing fails silently.

file trackergapsdashboard
